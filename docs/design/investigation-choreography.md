# Account investigation choreography

## Job and choice
Turn mixed account notes into a reviewed set of CRM changes. The previous view
showed counters but hid concurrent account work and had no complete final view.

Compared three structures: a chronological chat feed, an animated routing graph,
and a fixed account board. Keep the board: it preserves account position and exact
before/after records. A feed moves results away; a graph requires another surface
for review. Preserve the established editorial type, paper surfaces, teal selection,
and violet agent activity. No separate visual language is needed.

## Sequence
1. Keep the source input in place. Match passages to accounts.
2. Mark each active account while up to three account workers compare records.
3. Retain timestamped provider decisions in the run; show the latest three events.
   Account progress uses checked passages, not elapsed time or guessed progress.
4. Reveal received cards with a 220 ms fade and 5 px movement. Progress bars use
   280 ms transitions. Reduced-motion preference removes both effects.
5. At completion, show all account outcomes automatically. Selection after completion
   remains under user control. No focus moves and no automatic page scroll occurs.
6. Let the user inspect individual sources or approve the displayed plan together.
   Save sequentially through existing guarded operations, render each receipt, and
   stop on the first failed write. Earlier successful writes remain saved.
7. Show pending, saved, unchanged and unclear outcomes separately. A repeated run
   checks existing evidence and avoids duplicate writes.

## Boundaries
Activity labels describe observable work, not model reasoning. Production has no
artificial waits. The film may use a labelled simulated provider for rehearsal.
One action per passage remains the engine contract; this is not exhaustive repair
of every related record. Unclear evidence never becomes an approved change.

## Review evidence
Frontend design review: PASS for the presentation flow.
The integrated route was recorded with fictional records and a simulated provider:
matching, concurrent checks, risk before/after and source, plan approval, saved
outcomes, and a repeat with zero duplicate changes. Account selection preserves
input and frame. Desktop widths 1600, 1280 and 1024 fit the viewport; narrow layouts
scroll vertically. Light/dark and reduced motion were inspected. A fresh visual
critique led to explicit unresolved-evidence copy before approval, tighter account
rows, removal of finished progress bars, and precise completion counts. Theme
screenshots must wait for the existing color transition before judging contrast.

Residual limits: long result lists use panel scrolling. The local recording is a
backup demonstration, not evidence of live provider speed or classification quality.
